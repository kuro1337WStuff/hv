# 104 · Does the published ACPI table advertise the devices we implement?

**PASS · host memory fixture.** The publication validator accepted the expected guest memory map, IRQ9, PM1a registers and fixed `_S5_` package. Changing the advertised device fields while repairing each table's checksum caused refusal. A guest write to the FACS global lock did not. The validator left the backing bytes unchanged. A checksum alone would not distinguish the negative cases.

| Published field | Design and discriminating control |
|---|---|
| SCI and PM1a | SCI interrupt 9; event block `0x600`, 4 bytes; control `0x604`, 2 bytes. Re-sealed wrong IRQ, legacy addresses, lengths, GAS address space, bit width, bit offset, access size and high address bits were refused. |
| Absent hardware | Wrong optional block addresses and a hardware-reduced FADT flag were refused. This is a fixed hardware-full virtual profile, not validation of all conforming ACPI tables. |
| Shutdown AML | The entire 14-byte root `_S5_` package was checked. A separate one-byte change at each offset was refused, even with the DSDT checksum repaired. No AML method was executed. |
| Mutable NVS | Setting the FACS global-lock byte at offset 16 was accepted. Table identity checks do not freeze guest-writable NVS or implement lock handoff. |
