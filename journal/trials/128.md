# 128 · Can stale syscall state pass the cold entry check?

**Host result: no.** The clean, pinned layout passed. Setting bit 63 in any one of the eight stored VMCB fields below made the same entry guard reject it with `LinuxEntryColdAdjunct` (26). The control restored each byte before testing the next field; the clean image passed again at the end. A zero in this buffer is not proof of what a physical CPU would load or restore.

| Cold fields | Byte offsets from VMCB start |
|---|---|
| STAR, LSTAR, CSTAR, SFMASK | `0x600`, `0x608`, `0x610`, `0x618` |
| Kernel GS base | `0x620` |
| SYSENTER CS, ESP, EIP | `0x628`, `0x630`, `0x638` |

The zero requirement belongs to this diagnostic, not every AMD guest. Each field is read at full stored width, after existing fault checks. Offsets: AMD64 Architecture Programmer’s Manual vol. 2, Appendix B (VMCB state-save area), cross-checked against Linux [`struct vmcb_save_area`](https://github.com/torvalds/linux/blob/master/arch/x86/include/asm/svm.h). Kernel GS base is not the visible GS segment base.
