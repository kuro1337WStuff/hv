# 099 · Distinguishing a present UART from absent legacy serial ports

**PASS — host model.** The pinned x86-64 Linux interrupt-enable register (IER) existence probe distinguished one virtual COM1 UART from three absent legacy candidates. This is the existence check only: Linux did not run or register a tty.

[Reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7177844510) · [issue #85](https://github.com/kuro1337WStuff/hv/issues/85) · [implementation #89](https://github.com/kuro1337WStuff/hv/pull/89). Tested combined tree `330b16b3a2cadfc4b3acebd232f341e20286d305`, integrated on `feature/l1-handoff` at `17c5a001` after the independent PM1 byte change. No guest profile or firmware change on `main`.

Following the [Linux v6.18.60 probe](https://github.com/gregkh/linux/blob/v6.18.60/drivers/tty/serial/8250/8250_port.c#L1093-L1132), the host caller saved IER with DLAB clear, wrote zero and read the low nibble, wrote `0x0f` and read again, then restored the saved byte. The resulting classifications were:

| Candidate (base) | Saved IER | Masked reads: after zero / after `0x0f` | Result |
|---|---|---|---|
| COM1 (`0x3f8`) | `0x06` | `0x0 / 0xf` | Present |
| COM2 (`0x2f8`) | `0xff` | `0xf / 0xf` | Absent |
| COM3 (`0x3e8`) | `0xff` | `0xf / 0xf` | Absent |
| COM4 (`0x2e8`) | `0xff` | `0xf / 0xf` | Absent |

COM1's IER returned to `0x06`, but the empty transmitter's interrupt cause rearmed during the probe. Restoring the register did **not** restore its prior pending state. Reads and writes across all 24 absent addresses left COM1 state and TX untouched; nearby holes, malformed widths and a busy COM1 transmit were refused. Only the opt-in decoder returns `0xff` on absent reads. The original 047 model still refused a COM2 write.

**Reproduce:** on the feature revision above, compile `legacy_com_test`, `uart16450_test` and `guest_tx_capture_test` separately from `lab/tests/<name>.c` using x64 MSVC `/nologo /O2 /std:c11 /TC /W4 /WX`; run each executable. All three passed from an isolated export. No host port access, guest IRQ4 delivery, VM admission, or change to the held UART image.
