# 117 · Did the pinned command line and initramfs arrive intact in guest RAM?

**Yes in the host snapshot.** The [control](https://github.com/kuro1337WStuff/hv/blob/2771a481e8/lab/tests/linux_final_inputs_test.c) authenticated the retained kernel, initramfs and command line with the firmware's compiled SHA-256 pins, called the real `build_linux_layout`, then read the split pointers and initramfs length from the resulting boot parameters. It compared the destination bytes, not just the source hashes or the builder's return values. It established both destination ranges before reading either payload.

| Final range (exclusive end) | Independent expectation | Observed |
|---|---|---|
| Command line `[0x11000, 0x1107b)` | 123 bytes, with a single NUL as the final byte; pinned SHA-256 `5161eac9cd95353e2d47917e60e46bef0630b64f4bc2645f4cffd2b17f1bf958` | Exact; changing the first byte to a different non-NUL or flipping only the terminator produced a command-line mismatch. |
| Initramfs `[0x7e97000, 0x7fff964)` | 1,476,964 bytes; start is `(128 MiB − length)` rounded down to 4 KiB; pinned SHA-256 `99db7e0bb0742619d85deaab031ff7a539cd8e46cb6b7dd8ed8dd01196e3baa4` | Exact; flipping the first or last payload byte produced an initramfs mismatch. The page padding after the final byte is not part of the archive. |

**What the negative controls distinguish:** a shifted pointer, nonzero high pointer field, incorrect length or truncated backing failed the range check. When the command-line contents were wrong **and** backing ended one byte short of the initramfs, the result was `initramfs extent`, not a byte mismatch. Restoring the changes returned `exact`; all three staged pins still matched. In separate invocations a same-length altered **source** command line exited 1 with input-3 SHA mismatch; a one-byte-short source exited 1 at the file-size gate. Neither reached the copy controls.

**Reproduce on the feature revision:** compile `lab/tests/linux_final_inputs_test.c` with x64 MSVC `/nologo /O2 /std:c11 /TC /W4 /WX`; pass `vmlinuz-virt`, `initramfs.cpio` and `cmdline.bin`, in that order. The retained kernel was 12,649,472 bytes, SHA-256 `1e8ac7aebfab3f0fcb443eae94ad320efbbda51be91b928c32ca1740b44ebe9d`. An independent reader hashed the three inputs and derived the ranges above. The local program ran on reviewed tree `be14af3ef208706a0012d8a07747dbeb2c499a47`. The public feature checks on [PR #138](https://github.com/kuro1337WStuff/hv/pull/138) exercise devices, **not** these retained files.

The older layout test already compared positive copies. This trial adds source authentication, bounds before content comparison, and matched source-vs-destination faults. It does not change the runtime entry guard, exclude concurrent writes, give a page execute permission, or provide a Linux boot.
