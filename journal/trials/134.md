# 134 · Which optical sectors contain the Windows installation witness?

**A read by filename and a raw read by sector agreed on the same 64 bytes.** This is a reference for a future guest test. Windows did not execute, bind a driver or read these bytes. [Machine-readable witness](../reports/install-content-134.witness.json) · [functional matrix](../reports/functional-outcomes.svg).

| Input | Size or location | SHA-256 |
|---|---|---|
| Pinned candidate ISO | 3,839,819,776 bytes | `a11116c0645d892d6a5a7c585ecc1fa13aa66f8c7cc6b03bf1f27bd16860cc35` |
| Outer `sources/install.esd` | 3,135,611,742 bytes | `42d234f69a8cacb657ac67b24b72b40a3c3ce8844ec0d947c9e2ca862e819cfb` |
| File range | Offset 65,520; length 64 | `8d0dd15b53bcd7a6448f5fc564381655a87356b3f19909b3123143b55f0d9461` |

7-Zip streamed the full named UDF member into a host-side hash without extracting it to disk. Independently, UDF directory and allocation metadata mapped the range to **LBA 247,061, byte 2,032** on the ISO, i.e. absolute byte **505,982,960**. The raw read takes the last 16 bytes of that sector and the first 48 of LBA 247,062. Absolute media LBAs are not partition-relative UDF block numbers. Neither location nor expected digest was selected by searching the raw image for a match.

**Controls.** Shifting the first LBA by one while retaining the expected digest returned a mismatch (`72776bd9740844b75785fdf3792a1368b29a09dbbdfc7c209d6eef0fe419457f`). A read-only view ending one sector before the known end of the same image was refused on size, even though the requested bytes remained present. The original image was not truncated or mounted. The [ten host tests](https://github.com/kuro1337WStuff/hv/actions/runs/45743603206/job/139654242993) also cover a hole or continuation descriptor, a discontinuous allocation crossing, a short read during hashing, and a same-size byte change. Only the local trial used the private installation medium; CI used authored inputs.

**Repeat:** verify the full ISO digest first. From the [tested topic revision](https://github.com/kuro1337WStuff/hv/tree/467d05479b8a7c42903fca19e8186678c204fabd/lab#check-the-optical-installation-payload-without-booting-it), run the named member reader, sector mapper and raw verifier using the receipt above. The mapper is limited to this image layout and the hash-pinned parser; it is not a general UDF validator. A matching digest identifies content, not the publisher or trustworthiness of the media. No installation bytes were published.
