# 121 · What does the relocated decompressor actually clear?

The pinned x86-64 image specifies a BSS clear of **`[0x35cf400, 0x35e88e8)`**: 12,957 qwords, or 103,656 bytes. Neither end is a page boundary. The host verifier decoded the backward copy's endpoints and count, then the relocated clear's start and exclusive end. The copy ends exactly where the clear begins. These are guest-physical addresses in the fixed layout, not offsets in the inflated ELF.

| Part of the 26-page model window | Observed result |
|---|---|
| File-backed prefix `[0x35cf000, 0x35cf400)` | 1,024 original bytes preserved. Only 37 are nonzero; the last 384 are already zero. Testing only the byte immediately before BSS would miss a destructive clear. |
| BSS `[0x35cf400, 0x35e88e8)` | Every byte changed from `A5h` to zero. Omitting the first byte and omitting the last byte failed with distinct reasons. |
| Suffix `[0x35e88e8, 0x35e9000)` | All 1,816 guard bytes retained `A5h`. Rounding the clear up destroyed the guard; rounding down at the start destroyed the copied prefix. |

**Reproduce:** `python lab/linux/verify_relocation_bss.py PATH_TO_PINNED_VMLINUZ` on [feature PR #150](https://github.com/kuro1337WStuff/hv/pull/150). The 12,649,472-byte local kernel had SHA-256 `1e8ac7aebfab3f0fcb443eae94ad320efbbda51be91b928c32ca1740b44ebe9d`. Setup occupied `0x4000` bytes; the prefix came from file `[0xc10000, 0xc10400)`. Flipping a byte outside the inspected regions failed whole-image authentication. A separate calculation using the last 1,024 file bytes, exactly 103,656 zeros and 1,816 guards reproduced the model-window SHA-256 `d9228ca352ea18621ac4e8a645daa6ecbf67651feee2cbe2a69d0e30cd8448a3`.

The CLI ran locally on tree `63019bfad3e1ef16b684055dba4952f424e2cc0c`; the three [hosted feature checks](https://github.com/kuro1337WStuff/hv/actions/runs/45734531148) exercised the existing CPU/device controls, **not** the retained kernel. Feature integration: `3d42590e`. This is a byte model, not evidence of a runtime clear, absence of other writers, or executable-page safety. No VM, guest or permission change.
