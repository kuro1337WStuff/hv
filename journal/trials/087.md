# 087 · PIT channel 0 periodic reload

**Host controls passed. No VM or hardware clock was used.** [Work item #50](https://github.com/kuro1337WStuff/hv/issues/50) · [reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7176793387) · [implementation #53](https://github.com/kuro1337WStuff/hv/pull/53).

Linux's pinned [`pit_set_periodic()`](https://github.com/gregkh/linux/blob/f45ed76d6791cf72ff1265ee93511175bbbc2f18/drivers/clocksource/i8253.c#L154-L164) writes command `0x34`, then the low and high bytes of [`PIT_LATCH`](https://github.com/gregkh/linux/blob/f45ed76d6791cf72ff1265ee93511175bbbc2f18/include/linux/i8253.h). At 1,193,182 Hz input and kernel HZ=1000 the divisor is 1193 (`A9 04`), not exactly one millisecond. The [8254 datasheet, mode 2, figure 17](https://www.scs.stanford.edu/10wi-cs140/pintos/specs/8254.pdf) distinguishes the one-pulse low strobe from the rising edge. The model holds GATE high and accepts absolute completed input pulses, not elapsed host time.

| Host control | Observed |
| --- | --- |
| Initial arm, divisor 1193 | No edge with only the low byte written. After the completed count, OUT was low at pulses 1193 and 2386, and rose at 1194 and 2387. The second read at the same pulse did not create an edge. |
| Change divisor 5 to 3 while running | A partial count crossed the old boundary without reloading. Completing it mid-period preserved the old rise at 16; the next rise was at 19. |
| Long jump and invalid inputs | Crossing many periods left one consumable edge, not a backlog. The last low and high samples through `UINT64_MAX` remained distinct. An encoded zero counted 65,536; divisor 1, wrong width/port/command and backward time were refused without altering the sampled state. |
| Existing mode-4 IRQ0 fixture | Its deadline, access refusal, cancellation, pending IRQ and specific EOI controls still passed. Neither the fixture nor the profile manifest changed. |
