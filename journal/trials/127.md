# 127 · Does the selected Windows Setup image name the proposed storage controller?

**Partial evidence: AHCI chain found; modern virtio-SCSI support not established.** The scanner reviewed 11,539 model entries across 463 selected sections in 306 of 322 published INFs. None yielded the modern `1AF4:1048` device chain. Sixteen INFs could not be fully interpreted, so the scanner returned **inconclusive**, not “driver absent.” The complete raw-text census below is independent corroboration, not a substitute for Windows PnP.

[111](111.md) proposed a **modern virtio-SCSI PCI controller** for nested rehearsal. OVMF reading a disc does not give the Windows PE kernel a driver after firmware hands off. This inspection checks the selected Setup image rather than the installed OS or a driver repository on the host.

**Independent inventory:** without mounting either file, 7-Zip listed all entries and extracted the selected index's 322 published `Windows/INF/*.inf`, 296 top-level `Windows/System32/drivers/*.sys` and 309 package INFs from `DriverStore/FileRepository`. Every extracted pathname and file hash matched its WIM entry. All 309 package INF digests were also represented in the published set; a package copy is not independent proof of installation.

**Control:** in `mshdc.inf`, `AHCI_HDC.NTamd64...0x01` maps `PCI\CC_010601` to `msahci_Inst`. Its `.Services` section associates `storahci` with `msahci_Service_Inst_Client`, which declares boot start and `%12%\storahci.sys`. The in-image binary is an AMD64 PE (`0x8664`), 186,168 bytes, SHA-256 `688665b39022b82314f50d4d39c254f66e4aa7943f89a09afebb18ed049dc509`. The other two model decorations refer to Server products, not this index. No driver was loaded.

The first scanner rejected the entire AHCI control when it encountered `ExcludeID`. The corrected result preserves all 21 vendor/device/subsystem exclusions from `msahci_Inst` alongside the valid class-level chain. An explicitly excluded matching ID fails the synthetic control. **An AHCI driver in the image is not evidence of an optical device, a usable disk, or a selected boot-critical service for a particular controller.**

**False positive avoided:** `netl160a.inf` contains `PCI\VEN_1969&DEV_1048`, a different vendor. `DEV_1048` alone does not identify virtio-SCSI. Neither the published INFs nor their package copies contained the literal `VEN_1AF4` or `CC_0100`. The [virtio PCI transport](https://github.com/oasis-tcs/virtio-spec/blob/master/transport-pci.tex) distinguishes modern from transitional IDs; [Windows PCI ID rules](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/identifiers-for-pci-devices) distinguish vendor/device and compatible class matches.
