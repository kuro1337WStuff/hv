# 106 · What counts as two independent Linux cold boots?

**Host verifier passed. Actual qualifying Linux boots: 0 of 2.** A renamed capture, a second run ID or a second `PASS` line is not another cold boot. Conversely, identical serial output and terminal frames do not invalidate two independently witnessed starts. This trial tested the evidence check; it did not launch Linux.

`compare_cold_boots(pins, first, second)` returns each single-run PID 1, timer and virtual S5 observation in caller order. It keeps the broker's actual dispositions, including `ATTENTION`. It does not create a new `PASS` verdict.

| Required input | What the verifier checks |
|---|---|
| Same machine and build | Both dispatches and reviews match the frozen platform digest (including VM identity), profile, source revision and media digest. The operator independently binds the build and pinned guest inputs to the media. |
| Two cold starts | For each attempt, supply original host records reviewed as powered off and then freshly started, bound to that attempt's broker and terminal artifacts. The completed start must fall between the broker's boot request and its running observation. The two evidence intervals must not overlap, **through the terminal capture**, not just through startup. |
| Two completed guest observations | Each capture independently satisfies [088](088.md) and [090](090.md): pinned PID 1 marker, advancing timer and separately reviewed, unresumed S5 at the same terminal. Missing evidence on either side rejects the pair. |

All 24 tests passed on tree `21352a3a840d91610667cfb131e1d9559dcb8716`, including the retained 047 artifacts and predecessor-frame control. The new paired records were synthetic. Matching frames and TX preserved `ATTENTION` and `COMPLETE` in caller order. Reusing an attempt or an Off/start record, substituting a resume or broker row, mixing pins, overlapping the earlier terminal, or omitting the timer or S5 observation all failed. Without the private 047 archive, its three tests skip; they were **not** skipped in this trial.

**Trust boundary:** the check binds bytes, timestamps and reviews. It does not authenticate the capture provider or decide whether an arbitrary native event means “powered off.” If the same-VM transition cannot be established independently, do not issue the review. No VM state, firmware profile, page permission or timing baseline changed.
