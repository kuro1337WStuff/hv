# 092 · ACPI PM1a event status and enable

**Host PASS.** [Reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7177142268) · [#63](https://github.com/kuro1337WStuff/hv/issues/63) · [implementation #66](https://github.com/kuro1337WStuff/hv/pull/66) · [integration `21c389e0`](https://github.com/kuro1337WStuff/hv/tree/21c389e0c5f6714234117b6de02934ed822db105). Tested combined tree `97c4da2eb25bdd4ef8944a069caae7851b5dc26c`.

The generated FADT advertises a four-byte PM1a event block at guest port `0x600`, distinct from its two-byte control at `0x604`. The pinned ACPICA route splits the event block into two words: status at `0x600`, enable at `0x602`. [ACPI 6.5 tables 4.11–4.12](https://uefi.org/specs/ACPI/6.5/04_ACPI_Hardware_Specification.html#pm1-status-registers) define the bits; [Linux fixed-event initialization](https://github.com/gregkh/linux/blob/v6.18.60/drivers/acpi/acpica/evevent.c) and [legacy sleep](https://github.com/gregkh/linux/blob/v6.18.60/drivers/acpi/acpica/hwsleep.c) supply the register sequence. No Linux or ACPICA binary executed in this trial.

**Discriminating result:** with wake and global-lock status synthetically latched, enabling the global event left status `0x8020`. Writing `0x8000` to status cleared only wake, leaving `0x0020`. The subsequent fixed-status clear (`0xc731`) left status zero. Enable read back as `0x0020` after both clears. The test checked all 16 bit positions and refused invalid forms, misaligned accesses and oversized operands without changing register state or the caller’s output. Event writes never stopped the virtual machine model; only the separate control decoder accepted `OUTW 0x604, 0x3401` as a stop.

**Reproduce:** compile and run `lab/tests/power_event_test.c`, `lab/tests/power_request_test.c` and `lab/tests/power_tables_test.c` as separate C11 executables from the linked revision. All three passed with MSVC `/O2 /std:c11 /W4 /WX`, including the independent table walker’s corrupt/dangling controls.

Only the pinned scalar **word** path is modeled. ACPI also specifies byte access. Register readback is not a FACS lock handoff, an actual wake event, IRQ9/SCI delivery or evidence of Linux poweroff. No VM, host port I/O, deployment or change to bench admission.
