# 129 · Do all loaded kernel bytes match the authenticated source?

**Host result: yes, at the post-load checkpoint.** The loader’s entry byte (`fc`) still matched when we changed only the last file-backed byte. The new guard caught that change. It compares the complete protected-mode payload after materialization, before the original guest’s first denied fetch. It does not compare the setup header, zero-fill workspace or relocated kernel as if they were the same image.

The existing SHA-256 gate rejected a changed source. With authentic staging, the destination comparison passed at the exact end of both spans and rejected a one-bit change to the last byte. A one-byte-short source or RAM span, a shifted setup offset or GPA, and a shortened payload length each failed the extent check. Restoring the original input and geometry passed. Source and destination are compared byte-for-byte; the payload digest above independently identifies the file slice.
