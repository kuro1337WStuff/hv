# 123 · Which bytes survive the two overlapping Linux segment moves?

**Both file-backed destinations matched their original source bytes.** Linux v6.18.60 [`parse_elf`](https://github.com/gregkh/linux/blob/v6.18.60/arch/x86/boot/compressed/misc.c#L307-L337) snapshots the program headers, then moves `p_filesz` bytes per load segment. It does not copy or zero a `p_memsz`-only tail. The host control followed that step on the pinned inflated ELF in a bounded mutable buffer; an independent reader hashed the immutable file slices.

| Source → destination in the modeled physical layout | Bytes moved | SHA-256 after both moves |
|---|---:|---|
| `0x1200000 → 0x1000000` | 26,947,644 | `5e730b7ff6a3a268843330beeb007a2dbc0a15fd3a85b3f5a8c255c5b08ccb87` |
| `0x2c00000 → 0x2a00000` | 9,314,304 | `f69e3e101dd03155cae1f05c2a9b3a4df5d199df550cf3a37fb9d180335099a0` |

Both moves shift down 2 MiB and overlap their sources. The linked entry page at `0x3004000` matched [102](102.md). But its digest also matched in **both incorrect cases**: copying the first segment in descending block order corrupted its full destination, while using memory size for the second copy preserved both file digests but overwrote its tail. An entry-page check alone misses both faults.

Before the moves, the second segment's memory-only range `[0x32e2000, 0x3430000)` contained 757,222 nonzero bytes. Its SHA-256 stayed `7f6c654ec18a1e5fd0881c75dc7df3ce746ec18ace8bf4b986f021e3b650194a` in the correct case. In the oversized control, 626,728 bytes of extra source still lay inside the inflated file; those alone demonstrated damage. The rest of that *invalid* source came from explicitly marked synthetic guard space, not the kernel image. Whole-image authentication also rejected a one-byte substitution before inflation.

The retained 12,649,472-byte kernel had SHA-256 `1e8ac7aebfab3f0fcb443eae94ad320efbbda51be91b928c32ca1740b44ebe9d`. The original `inspect_exec_layout.py` CLI and its six unit tests passed on the same local tree `8df65421dfaadf8c3753cd9e35b3d4838e568508`.
