# 112 · Which UART would the pinned Linux probe identify at COM1?

**16450 on the modeled COM1.** The UART passed the interrupt-enable register (IER) existence test, reported no FIFO, and returned both values written to its scratch register (SCR). A port can pass existence detection yet look like an 8250: in two controls, only SCR writes were ignored. Neither control was mistaken for an absent port or a 16450.

| COM1 case | SCR before | Read after writing `a5` | Read after writing `5a` | SCR after restore | Classification |
|---|---|---|---|---|---|
| Existing virtual UART | `37` | `a5` | `5a` | `37` | 16450 |
| Same port, read-only SCR initially `a5` | `a5` | `a5` | `a5` | `a5` | 8250 |
| Same port, read-only SCR initially `5a` | `5a` | `5a` | `5a` | `5a` | 8250 |

The [standard x86 COM1 descriptor](https://github.com/gregkh/linux/blob/v6.18.60/arch/x86/include/asm/serial.h) skips the modem loopback test, **not** the IER test. The host caller replayed the [configuration-mode and FIFO probe](https://github.com/gregkh/linux/blob/v6.18.60/drivers/tty/serial/8250/8250_port.c#L1134-L1190), then the [two-pattern scratch discriminator](https://github.com/gregkh/linux/blob/v6.18.60/drivers/tty/serial/8250/8250_port.c#L874-L891). Each control still performed both reads through the existing model. The expected classification depends on both readbacks, not on the label attached to the fixture.

All three cases read interrupt identification `02` (FIFO bits `00`). That read acknowledged the pending transmitter-empty cause: restoring the configuration is not restoring the interrupt. Final LCR `03`, MCR `08`, IER `06`, divisor `1234`, **zero transmitted bytes** in each classification. COM2–4 retained the separate absent-port behavior from [099](099.md).
