# 100 · Byte access to the ACPI PM1a event block

**PASS — host only.** The four bytes advertised by the generated FADT can now be read or written individually. Clearing one status bit through its byte left the bit in the other byte intact. A byte write could deassert the ACPI interrupt source but could not acknowledge an in-service interrupt or request shutdown.

[Reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7177845483) · [issue #86](https://github.com/kuro1337WStuff/hv/issues/86) · [implementation #88](https://github.com/kuro1337WStuff/hv/pull/88). Tested tree `9f6f10844cb2a6716281971834a6d3e072efd136`, merged on `feature/l1-handoff` at `c78c5fce`. Trial numbers follow reservation order, not feature merge order.

| Initial state and access | Observed result |
|---|---|
| Status `0x8020`; write `0x20` at `0x600` | Global status cleared; wake status remained (`0x8000`). |
| Status `0x8020`; write `0x80` at `0x601` | Wake cleared; global status remained (`0x0020`). |
| Write `0xff` to enable low (`0x602`), then enable high (`0x603`) | Aligned enable word read `0x0020` after each; the high byte read zero. |
| Clear global status while the IRQ9 route is in service | Source deasserted; slave/master in-service bits remained `0x02`/`0x04`. Wake alone produced no source. |
| Cross a register boundary with a word, use width 257, or pass an oversized byte | Refused without changing either register or the caller's value. The event decoder refused `0x604`; only the separate aligned control-word decoder accepted the S5 request. |

**Reproduce:** from the feature revision above, build `power_event_test`, `power_sci_test`, `power_request_test`, and `power_tables_test` individually from `lab/tests/<name>.c` with x64 MSVC `/nologo /O2 /std:c11 /TC /W4 /WX` and run each executable. All four passed in an isolated export. [ACPI §4.8.3.1](https://uefi.org/specs/ACPI/6.5/04_ACPI_Hardware_Specification.html#pm1-status-registers) specifies byte or word access; [092](092.md) and [098](098.md) document the original word behavior and PIC service. No guest SCI, physical event, Linux execution, power transition, or VM admission was observed.
