# 091 · One PIT clock through periodic, one-shot and disable

**Host PASS.** [Reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7177141163) · [#62](https://github.com/kuro1337WStuff/hv/issues/62) · [implementation #65](https://github.com/kuro1337WStuff/hv/pull/65), [integration `021284bc`](https://github.com/kuro1337WStuff/hv/tree/021284bcb901d1994209b5bb55ac3cf462ab75ef). Tested tree `bfbaf9bb4a8613b554b7d21b011ccc9247476f1a`.

[089](089.md) exercised periodic edges through the PIC. This trial applied the [pinned Linux channel-0 programming sequence](https://github.com/gregkh/linux/blob/v6.18.60/drivers/clocksource/i8253.c) to a single absolute input-pulse counter, using [8254 figures 15, 17 and 19](https://www.scs.stanford.edu/10wi-cs140/pintos/specs/8254.pdf) as the timing reference. Only OUT and its rising-edge latch were measured.

| Input | Observed in the host model |
|---|---|
| Switch the 1193-pulse periodic timer to mode 4 while OUT is high vs. low | Only low → high at the control write generated an immediate request. An incomplete count did not start a shot. |
| Complete mode-4 count 15 | OUT stayed high at +15, went low at +16, rose at +17. Rewriting while low did not end that strobe until the next pulse; repeating a timestamp created no second edge. |
| Linux disable: `0x30`, two zero count bytes, final `0x30` | The last command cancelled the mode-0 count but did not erase an IRQ already pending at the PIC. Without the last command the zero-encoded 65536 count produced a rise at +65537. |
| End of the 64-bit cursor | A zero-encoded mode-4 count fell at `UINT64_MAX-1` and rose at `UINT64_MAX`. A later shot did not wrap into the current time. |

**Reproduce:** compile `lab/tests/pit_periodic_test.c` and `lab/tests/pit_pic_test.c` as separate C11 executables and run both at the linked integration revision. MSVC `/O2 /std:c11 /W4 /WX`: periodic controls, the new switch/strobe/disable controls, and the original logical one-shot IRQ0 controls all passed. The original one-shot model’s logical deadline is not the mode-4 pin timing above.

No VM boot, physical timing measurement, clock calibration or Linux handler delivery. The next clock integration needs to keep channels 0 and 2 on the same virtual input timebase without confusing their independent counters.
