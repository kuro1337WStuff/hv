# 118 · Does a fresh vCPU inherit bytes from an old legacy FP image?

**Not in this host control.** Starting from either `A5` or `5A` in every byte, the constructor produced the same 512-byte FXSAVE64 image. It changed none of the 112 adjacent GPR bytes or the 16-byte guard on either side of the bank. It initializes a private image before first use; it is not a processor reset, `FXRSTOR`, or a resume operation.

The oracle used raw little-endian offsets, not C struct members: bytes `0,1` were `7f 03` (FCW `037f`); bytes `24,25` were `80 1f` (MXCSR `1f80`); all other bytes were zero. Both prior fills yielded FSW/TOP `0`, abridged FTW `00` (all slots empty) and mask `00000000`. Empty tags do **not** themselves erase the x87 payloads; the control checked the payloads, XMM0–15, saved pointers, reserved bytes and tail as well. The zero mask is not a measurement of hardware capability.

**Why not call this RESET?** AMD64 APM Vol. 2, §14.1.3, Table 14-3 distinguishes the x87 control word after hardware RESET (`0040h`) from the one after software `FINIT` (`037Fh`). Full and abridged tag encodings also differ. The constructor chooses initialized software state; scrubbing every unused byte is an isolation policy, not a claim about silicon. [AMD64 APM Vol. 2, publication 24593](https://docs.amd.com/v/u/en-US/24593).
