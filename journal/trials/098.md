# 098 · ACPI fixed event through both legacy interrupt controllers

**PASS — host model.** An enabled ACPI global-status bit presented a level on IRQ9. When the route was ready and unmasked, the two virtual 8259s accepted it as vector `0x39`. That is controller acceptance, **not CPU or guest-handler delivery**.

[Reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7177683414) · [#79](https://github.com/kuro1337WStuff/hv/issues/79) · [implementation #84](https://github.com/kuro1337WStuff/hv/pull/84), landed on `feature/l1-handoff` at `f0776108`. Tested merge tree `5c4a8ebf8fe5a2a934e0ab6c00bbcf13192d8d14` includes [097](097.md). No firmware change on `main`.

| Stimulus | Checked observation |
|---|---|
| Read generated FADT; configure PIC pair | `SCI_INT=9`, PM1a status `0x600`, enable `0x602`. Incomplete initialization, edge mode, a masked slave IR1 or a masked master IR2 each prevented acceptance. |
| Latch WAK only, then latch GBL with GBL enabled | WAK alone never asserted SCI. Clearing GBL while masked removed the source; later unmask did not resurrect it. |
| Accept with GBL asserted and both masks open | Returned `0x39`; slave in-service `0x02`, master in-service `0x04`. A second take failed without altering its output. |
| Write specific EOIs | `0x61` to `0xa0` cleared only the slave; `0x62` to `0x20` cleared only the master. Either remaining bit blocked a second take. Wrong-target and duplicate EOIs were refused without mutation by this fixture; that refusal is not a hardware bus fault. |
| Replay the [Linux mask-and-ack sequence](https://github.com/gregkh/linux/blob/v6.18.60/arch/x86/kernel/i8259.c#L158-L199) | Slave mask read `0xfd`, then `0xff` after masking IR1. Master mask stayed `0xfb`. After slave-then-master EOIs, restoring `0xfd` allowed another acceptance only if GBL was still asserted. Clearing GBL did not erase either controller's existing service. |
