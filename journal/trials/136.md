# 136 · Is the reported last optical sector actually readable?

**Yes on the authored host medium.** The same immutable geometry now bounds `READ(10)` and supplies the plain `READ CAPACITY(10)` reply. On a three-sector medium, the eight-byte reply was `00 00 00 02 00 00 08 00`: last LBA **2**, block size **2,048**. Asking for capacity performed no backing read.

| Request using the returned geometry | Observation |
|---|---|
| One sector at LBA 2 | One backing lookup. All 2,048 returned bytes matched the authored final sector, with caller guard bytes intact. |
| Two sectors starting at LBA 2 | Refused before reading; the entire output and its guard bytes were unchanged, despite enough output space for both sectors. |
| One sector at LBA 3 | Refused before reading; output unchanged. |

**Windows installation medium, metadata only:** the [trial 134 receipt](../reports/install-content-134.witness.json) records **3,839,819,776 bytes**. That is **1,874,912** full sectors. Passing only that byte count to the compiled fixture produced `001c9bdf00000800`: last LBA **1,874,911**, block size 2,048. This was not a read of the installation medium's final sector. No ISO, VM, device or driver was opened for this trial.

Empty media have no last block, so the capacity request failed without writing a reply. At or above last LBA `0xffffffff`, the reply carries the standard sentinel rather than wrapping or claiming the exact capacity. The [firmware checks that sentinel](https://github.com/tianocore/edk2/blob/556dcfb466e9f05affeaff881d738807f8156d3c/MdeModulePkg/Bus/Scsi/ScsiDiskDxe/ScsiDisk.c#L3141-L3159) before switching commands. This fixture does **not** implement READ CAPACITY(16), partial-medium queries, sense data or AHCI. The [pinned command builder](https://github.com/tianocore/edk2/blob/556dcfb466e9f05affeaff881d738807f8156d3c/MdePkg/Library/UefiScsiLib/UefiScsiLib.c#L736-L756) and [firmware parser](https://github.com/tianocore/edk2/blob/556dcfb466e9f05affeaff881d738807f8156d3c/MdeModulePkg/Bus/Scsi/ScsiDiskDxe/ScsiDisk.c#L3463-L3474) document the supported wire format.
