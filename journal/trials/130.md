# 130 · Which backing supplies the reset address?

**Host result: the final 16 bytes of CODE, in one read.** Windows x64/MSVC and [Ubuntu/GCC](https://github.com/kuro1337WStuff/hv/actions/runs/45740317054/job/139643414508) observed `reset: backing=CODE offset=0x37bff0 count=16 reads=1`. Both used synthetic bytes, not OVMF instructions. No guest reset or firmware execution was tested.

The [pinned OVMF layout](https://github.com/tianocore/edk2/blob/556dcfb466e9f05affeaff881d738807f8156d3c/OvmfPkg/Include/Fdf/OvmfPkgDefines.fdf.inc#L53-L67) places VARS at `0xffc00000` for `0x84000` bytes and CODE at `0xffc84000` for `0x37c000` bytes. The 4 GiB upper bound is exclusive. [Trial 111](111.md) proposed the question; the fixture uses separate immutable arrays and an instrumented backing callback. Its oracle is independent of the decoder: 16 explicit bytes and a separately checked backing ID, offset and count.

| Request | What the host fixture observed |
|---|---|
| `0xfffffff0`, 16 bytes | Returned `39 a4 71 0b ce 52 18 f0 65 2d bc 83 47 9a 06 de`. A neighbor and the VARS tail have different sentinels. Output guards intact. |
| Same request, last 4 KiB of CODE unavailable | Refused without calling the backing or changing the destination or guards. The last byte of the preceding page remained readable. |
| `0xfffffff0`, 17 bytes, with ample output capacity | Refused before backing access, even when the backing advertises an extra byte. A VARS→CODE straddle was also refused. No partial copies. |

**Reproduce:** on [feature revision `2771cbca`](https://github.com/kuro1337WStuff/hv/commit/2771cbca14290a9c1a288ebecf10ba35c7fe51c9), run `cc -std=c11 -O2 -Wall -Wextra -Werror lab/tests/ovmf_flash_test.c -o /tmp/ovmf-flash && /tmp/ovmf-flash`. Local build: x64 `cl /TC /std:c11 /O2 /W4 /WX`. Both exited 0. All five feature CI jobs passed on tree `141598427d749236626b0ca17cad5d7c12d5b0ba`; the guest UEFI job actually ran this fixture.
