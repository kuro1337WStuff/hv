# 131 · Which optical controller should the nested Windows rehearsal target?

**Change the rehearsal target to Q35/ICH9 AHCI with one read-only ATAPI CD-ROM.** Both routes have an OVMF optical path in source. Only AHCI has a positive controller-driver candidate in the selected Windows Setup image. That is a reason to investigate AHCI first, not a reason to boot Windows. This decision changes neither the AMD host nor the physical design. [Issue #170](https://github.com/kuro1337WStuff/hv/issues/170) · [reservation 131](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7180436930).

| Layer | [111](111.md): i440FX/PIIX4 + modern virtio-SCSI | Proposed: Q35/ICH9 + AHCI/ATAPI |
|---|---|---|
| Guest-visible device | PCI `1AF4:1048`, modern virtio PCI transport and request queue, one CD-ROM LUN. | QEMU 9.2 reference: [built-in `ich9-ahci`][q35] at `00:1f.2`, [Intel SATA, revision 02][class], [device `2922`][did], [AHCI programming interface and MMIO BAR5][abar]: `8086:2922`, class/subclass/interface `01/06/01`. Choose one ATAPI CD-ROM on port 0, no port multiplier, no hard disk. This is a proposed attachment, not a device inventory. |
| Firmware before handoff | `Virtio10Dxe` exposes the modern transport; `VirtioScsiDxe` negotiates features, sets up the queue and supplies Extended SCSI Pass Thru. | `SataControllerDxe` accepts the SATA class, [reads the implemented-port bitmap and publishes IDE Controller Init][sata]. `AtaAtapiPassThru` uses it, tests the controller class, and [enumerates before publishing ATA and Extended SCSI Pass Thru][pass]. An [ATAPI port signature and successful IDENTIFY PACKET][identify] distinguish the CD-ROM branch from ATA disk; [AHCI packet commands][packet] carry the SCSI requests. The optical child is not an `AtaBusDxe` disk. |

Keep 111's cold, single-BSP `OvmfPkgX64`, `edk2-stable202611` at `556dcfb466e9f05affeaff881d738807f8156d3c`, 4-MiB split CODE/private VARS, non-SMM and Secure Boot off. The [DSC selects the components][dsc]; the [FDF stages them in DXE][fdf]. Neither says that a controller responded. Both routes converge on `ScsiBusDxe` ([child SCSI I/O][child]), `ScsiDiskDxe` ([CD-ROM Block I/O, initially 2,048-byte blocks and read-only][cd]), Disk I/O, El Torito partition and FAT boot image. Change the chipset assumptions too: [Q35 MCH and ICH9 PM function][mch] replace i440FX and PIIX4 PM; working PCI resources, port state, guest-private DMA buffers, interrupt/completion handling and a bounded read-only backing must replace virtqueue semantics. Neither route supplies the guest reset-to-DXE platform required by 111.

**Evidence after firmware ends.** [127](127.md) inspected `sources/boot.wim` (SHA-256 `cbcca3c293b2dd3ceaf33dc83bde3071fe30cc51ea988bb07efe0dcb98085d68`), boot index **2**, Windows Setup AMD64 `10.0.19041.1288`. Of 322 published INFs, 306 yielded 11,539 inspected model entries, none establishing the modern virtio-SCSI chain; 16 were incompletely interpreted. That is inconclusive, not proof of absence.

For AHCI, the retained index-2 `mshdc.inf` client model maps `PCI\CC_010601` to `msahci_Inst` (line 165). All 21 `ExcludeID` entries (347–367) specify `VEN_8086` with device `2653`, `27C5` or `2829` and a subsystem; none can match `DEV_2922`, regardless of subsystem. The associated `storahci` service (480) names `msahci_Service_Inst_Client`, boot start, `%12%\storahci.sys` (490). Trial 127 found the AMD64 binary, 186,168 bytes, SHA-256 `688665b39022b82314f50d4d39c254f66e4aa7943f89a09afebb18ed049dc509`. These are **static eligibility facts**, not a new scan, PnP ranking, service selection or driver load.

**Still missing:** Windows must enumerate the optical child, bind its own CD-ROM class stack and read the outer installation filesystem after EFI boot services end. A controller INF says nothing about the child, a read of the El Torito FAT image says nothing about reads of the install image, and the WinPE RAM disk is not an install target ([107](107.md)). No writable target, Setup run or installed OS is evidenced.

**One next host-only fixture — distinguish optical child from controller.** Against 127's manifest-checked, read-only index-2 INF/SYS inventory, hold the AHCI controller identity fixed and supply an authored INQUIRY response for one child. Positive: peripheral type 5 (`CdRom`, generic `GenCdRom` in the [Windows SCSI ID table][ids]); require a matching optical model for this index, its resolved install/service sections and the referenced AMD64 driver in the same inventory. Negative: change only the peripheral type to 0 (`Disk`, `GenDisk`); the optical chain must no longer match, even though the `storahci` evidence is unchanged. Record the input type, derived ID, exact INF line/section, service, SYS path and manifest digest for the positive, and absence of an optical match for the negative. An uninterpretable rule or missing positive witness leaves the optical question open. This tests static child-driver evidence only. No fixture, VM, guest software or driver ran for this decision; no media changes or passthrough.
