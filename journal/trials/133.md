The timing view accepts three comparisons: distinct builds in the same execution mode, native versus physical guest on the same platform, or the same guest binary with one declared feature off versus on. The last requires the recorded controls digests to distinguish the two states. All require independent boots, matching work and observed inputs. A signed elapsed delta is candidate minus baseline, so negative is faster. A matched result is descriptive, not a claim of statistical significance or VM invisibility.

**Verification boundary:** local controls covered mismatched platforms/modes, reused receipts, conflicting functional cells, wrong feature-state binding, and absent cohorts. A Windows symlink test skipped without the required privilege; the SVGs were opened and visually inspected. The timing-control tests use invented in-memory values only. No timing numbers from those tests or from reference screenshots are in the published figures. No VM, physical deployment, malware or performance run.
