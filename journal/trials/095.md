# 095 · Virtual cycles and PIT pulses from the same elapsed time

**Host PASS.** [Reservation](https://github.com/kuro1337WStuff/hv/issues/13#issuecomment-7177495684) · [#72](https://github.com/kuro1337WStuff/hv/issues/72) · [implementation #77](https://github.com/kuro1337WStuff/hv/pull/77) · [integration `61dfed1c`](https://github.com/kuro1337WStuff/hv/tree/61dfed1c774bb7ab7ef05165587260bcd58c92f7). Tested source tree: `9ce72fccda7cf3637cc07fb27ef503e98045121f`.

[093](093.md) established the shared PIT pulse source. The new host model consumes an explicitly supplied absolute nanosecond timestamp. It floors total elapsed time independently at the declared virtual cycle rate and at 1,193,182 PIT pulses per second. Reads do not advance either clock. Cycles wrap modulo 2⁶⁴, not the PIT cursor. Zero rate and backward time are refused without changing state.

**Measured synthetic interval:** at 2,500,000,000 virtual Hz, polling channel 2’s live count on a 31 ns grid first saw the `ff → fe` and `fe → fd` MSB transitions at 215,419 ns and 429,970 ns respectively. The counter advanced **536,378 virtual cycles over 256 PIT pulses**. Independently rounding each ideal transition time up to the next polling instant and then flooring the virtual cycle count produced the same difference: `1,074,925 − 538,547`. An ideal unsampled interval is about 536,380.87 cycles; it is not the test oracle for sampled endpoints.

Other controls: at 838 ns the clock reported 2,095 cycles and zero PIT pulses; at 839 ns it reported the first PIT pulse. Dividing an advance into steps yielded the same observed state as one bulk advance, even with channel 2 gated and IRQ0 masked. A backward sample within the same PIT pulse was refused; repeated time preserved the outstanding read byte and pending request. At `UINT32_MAX` virtual Hz the cycle count wrapped from `UINT64_MAX` to 3 across one ns without advancing the PIT.

**Reproduce:** compile and run `lab/tests/pit_cycle_clock_test.c` and `lab/tests/pit_shared_test.c` separately from the linked integration using x64 MSVC `/O2 /std:c11 /W4 /WX /TC`. Both passed. No host cycle counter was read, no guest instruction executed, and these figures do not measure either Ryzen processor or establish a Linux clocksource.
